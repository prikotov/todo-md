# TASK-feat-exclude-config: Ключ exclude в .todo-md.php — исключать каталоги из валидации

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

`Parser::findTodoFiles()` рекурсивно собирает **все** `.todo.md` под `todo/` без возможности исключить подкаталоги, поэтому `todo-md validate` без аргументов валидирует всё подряд — включая архив завершённых/отменённых задач.

Живой кейс (репозиторий-потребитель `task-orchestrator`, todo-md v0.4.0): архив `todo/done/` разросся до 280+ файлов; форматы валидации строжеют от версии к версии (строгие даты Change History, формат `assignee`, обязательные секции шаблона), а исторические файлы никто не мигрирует — они заморожены по процессу. Полный прогон валидатора даёт 303 файла / 866 ошибок, из которых почти все — архив, а живые задачи чисты. Шум маскирует новые реальные ошибки: полный прогон бесполезен как сигнал.

Обходной путь на уровне проекта-потребителя возможен (вызывать validate с явными целями: корень + backlog), но он дублирует логику сбора файлов в каждом потребителе и не даёт «полной» проверки одним вызовом. Родственная потребность подтверждена ретроспективой серии задач потребителя (2026-11-24) и решением владельца.

### Варианты или путь решения (Solution Sketch)

Ключ `exclude` в `.todo-md.php` — список подкаталогов `todo/` (относительные пути), исключаемых из рекурсивной валидации:

```php
return [
    'roles' => [/* ... */],
    'agents' => [/* ... */],

    // Архив завершённых/отменённых задач: исторический дрейф форматов
    // не должен тонуть в шуме живой валидации.
    'exclude' => ['done', 'cancelled'],
];
```

Реализация: `Parser::findTodoFiles()` принимает опциональный список исключений и пропускает перечисленные каталоги при обходе итератора; `cli_validate` передаёт в него `exclude` из конфига. Семантика — в Must Have.

### Ожидаемый результат (Expected Result)

Потребитель задаёт `'exclude' => ['done', 'cancelled']` в `.todo-md.php` — и `todo-md validate` валидирует только живые задачи, архив не создаёт шума. Пустой/отсутствующий ключ — поведение как сейчас (обратная совместимость). Прямая file-цель валидируется всегда, даже из исключённого каталога.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)

> Как владелец проекта-потребителя с большим архивом `todo/done/`, я хочу исключать архивные каталоги из валидации через конфиг, чтобы полный прогон `todo-md validate` показывал только реальный дрейф живых задач.

### Цель по SMART (Goal)

В v0.5.x: `.todo-md.php` поддерживает ключ `exclude`; `findTodoFiles` уважает его при рекурсивном обходе; CLI `--exclude` для разового исключения; документация (CONFIG.md + validate help) и fixture-тесты обновлены. Критерий: fixture-тесты зелёные, потребитель-репозиторий с `exclude => ['done', 'cancelled']` валидируется без архивного шума.

## 2. Контекст и Границы (Context and Scope)

*   **Где делаем:**
    *   `src/TodoMd/Parser.php` — `findTodoFiles(string $target, array $exclude = [])`: пропуск исключённых каталогов в `RecursiveIteratorIterator` (сравнение относительного пути от `searchRoot`).
    *   `src/bootstrap.php` — `cli_validate()`: чтение `exclude` из конфига (по аналогии с `roles`/`agents` в `Validator::loadConfigFile`), передача в `findTodoFiles`; опция `--exclude=dir[,dir]` (merge с конфигом); обновление `validateHelp()`.
    *   `docs/todo-md/reference/CONFIG.md` — документация ключа.
    *   `tests/` — fixture-тесты: структура с `todo/done/`, поведение exclude (фильтрация) и BC (пустой ключ — всё как раньше).
*   **Текущее поведение:** `findTodoFiles(string $target)` — рекурсивный обход без фильтров; конфиг — 5 ключей (`roles`, `agents`, `models`, `thinking_levels`, `strict`) в `Validator::loadConfigFile()`.
*   **Прецеденты для переиспользования:** паттерн чтения ключей конфига в `loadConfigFile` (массив строк, фильтр `is_string`); fixture-структура существующих тестов.
*   **Критичные конвенции:** PHP 8.4, `declare(strict_types=1)`, читаемость важнее производительности; `make check` (lint + валидация + тесты) перед PR.
*   **Границы (Out of Scope):** изменение ID-резолвинга (`Parser::findFileById`, `Board::resolveRoot`) — `set/done/review` по ID работают как раньше; exclude для `export-jsonl`/`dashboard` (отдельная задача при потребности); ключи конфига сверх `exclude`; CLI-флаги кроме `--exclude`.

## 3. Требования, MoSCoW (Requirements)
### 🔴 Обязательно (Must Have)

- [ ] Ключ `exclude` в `.todo-md.php`: список относительных путей от `todo/` (например, `['done', 'cancelled']`), исключаемых из рекурсивной валидации на любом уровне вложенности.
- [ ] Пустой/отсутствующий ключ — поведение идентично текущему (обратная совместимость init-контракта: проекты-потребители не ломаются при обновлении).
- [ ] Явная file-цель (`validate todo/done/TASK-x.todo.md`) валидируется всегда, даже из исключённого каталога (явное указание важнее exclude).
- [ ] Fixture-тесты: (а) каталог из exclude не попадает в выборку; (б) без exclude выборка как раньше; (в) file-цель из исключённого каталога валидируется.
- [ ] `docs/todo-md/reference/CONFIG.md` дополнен ключом; `validateHelp()` обновлён.
- [ ] `make check` — зелёный.

### 🟡 Желательно (Should Have)

- [ ] CLI-опция `--exclude=dir[,dir]` в `cli_validate` (merge с конфигом) для разового исключения.
- [ ] Поддержка глобов в exclude (например, `release-*`) — если удорожание реализации минимально; иначе отложить.

### ⚫ Не будем делать (Won't Have)

- [ ] Exclude не влияет на ID-резолвинг (`findFileById`): `todo-md set/done/review TASK-ID` по архивной задаче работают как раньше.
- [ ] Exclude не применяется к `export-jsonl`, `dashboard`, `init`.
- [ ] Никаких изменений существующих ключей конфига и формата валидации.

## 7. Риски и зависимости (Risks and Dependencies)

- Риск 1: потребители могут случайно исключить живые каталоги (например, `backlog`) и не заметить дрейфа — документация CONFIG.md должна явно предупреждать; семантика «exclude — только архив» как рекомендация, не ограничение.
- Риск 2: сопоставление относительных путей на разных ОС (разделители) — нормализовать через реальный `getPathname()` относительно `searchRoot`, тест на вложенность.
- Зависимостей нет; целевая версия — следующий минорный релиз (BC-совместимое расширение конфига).
