# TASK-cli-env-model-autofill: Автозаполнение модели и уровня мышления в create/start

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
Постановщики и исполнители создают задачи и стартуют их с голой ролью — `Разработчик (pi)`. Модель и уровень мышления в полях `author`/`assignee` не попадают, хотя истина для них лежит в окружении харнесса (`PI_MODEL`, `PI_REASONING_LEVEL`). Из-за этого в задачах нет данных «кто на чём реально работал»: срез по моделям пуст, статистика стоимости и качества по моделям не строится, а агенты полагаются на самоописание модели, которое LLM даёт недостоверно.

### Варианты или путь решения (Solution Sketch)
- В `create` и `start` дописывать `@модель~уровень` к участнику вида `Роль (pi)` из окружения харнесса; для агентов без стабильных переменных окружения запись не трогать.
- Флаг `--no-model` как отключение; некорректные значения окружения и значения вне списков `models`/`thinking_levels` конфига проекта игнорировать, чтобы автозаполнение не ломало валидацию.

### Ожидаемый результат (Expected Result)
Новые задачи и старты фиксируют модель и уровень мышления без ручного ввода: `author: Разработчик (pi@mimo-v2.6-flash~high)` уже при создании. Валидация строгим режимом остаётся зелёной, старые задачи не затронуты.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> Как владелец проекта, я хочу, чтобы в задачах автоматически фиксировались модель и уровень мышления исполнителя, чтобы видеть срез «кто, на чём и на каком уровне работал» без дисциплины от агентов.

### Цель по SMART (Goal)
- [ ] `create` дописывает `@модель[~уровень]` в `author` из `PI_MODEL`/`PI_REASONING_LEVEL` для голой роли `Роль (pi)`, `start` — в `assignee`.
- [ ] Уже указанная модель не перезаписывается; для агентов без переменных окружения запись не меняется; флаг `--no-model` отключает обогащение.
- [ ] Обогащение не может сломать валидацию: невалидный env и значения вне `models`/`thinking_levels` конфига игнорируются.

## 2. Контекст и Границы (Context and Scope)

*   **Где делаем:** `src/TodoMd/Board.php` (`withEnvModel`, `create`, `transition`), `src/bootstrap.php` (`cli_create`, `cli_transition`, help).
*   **Текущее поведение:** `create` пишет `author` как передан; `start` пишет `assignee` как передан; модель никогда не выводится из окружения.
*   **Прецеденты для переиспользования:** `docs/todo-md/reference/MODELS.md` — формат участника, словари уровней `Parser::THINKING_LEVELS`, правило «источник истины — env харнесса».
*   **Критичные конвенции:** формат участника `Роль (агент[@модель[~уровень]])` и его проверка — `Validator::validateActor`.
*   **Границы (Out of Scope):** валидатор не меняется (наследие старых задач без модели остаётся валидным); обогащение полей `reviewer`/`approver`/`consultants`/`informed` и команды `set` не входит в задачу; для не-pi агентов переменные окружения не изыскиваются.
