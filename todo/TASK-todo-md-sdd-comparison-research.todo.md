# TASK-todo-md-sdd-comparison-research: Ресёрч — сравнение todo-md с SDD-подходами (OpenSpec, BMAD и др.)

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Непонятно, чем todo-md отличается и в чём похож на инструменты класса SDD (Specification-Driven Development) — сначала спецификация/план, потом код.
- В сообществе сейчас активны конкретные реализации SDD: **OpenSpec**, **BMAD** (упоминаются в видео).
- Без внятного сравнения позиционирование пакета в README размытое: читатель не понимает, когда выбирать todo-md, а когда — SDD-инструмент.

### Варианты или путь решения (Solution Sketch)
- Сделать ресёрч: собрать, какие SDD-подходы и инструменты есть сейчас, как они устроены, какие задачи решают.
- Чётко сформулировать отличия и сходства с todo-md (формат хранения, workflow, связь с кодом, роль AI).
- Оформить результат как отдельный документ-ресёрч, на основании которого **позже** (отдельной задачей) сделаем раздел в README.

### Ожидаемый результат (Expected Result)
- Есть документ-ресёрч со сравнительной таблицей и выводами.
- Понятно, где todo-md = «то же самое», а где — «другая ниша» (или пересекается).
- Ресёрч — готовая база для будущего раздела README про позиционирование.

## 1. Concept and Goal (Концепция и Цель)
### Story (User Story или Job Story)
> **Job Story:** Когда я рассказываю про todo-md (в README, в разговоре), я хочу иметь под рукой чёткое сравнение с популярными SDD-инструментами, чтобы точно объяснять, кому и зачем нужен todo-md.

### Goal (Цель по SMART)
*S (Specific) — Конкретно | M (Measurable) — Измеримо | A (Achievable) — Достижимо | R (Relevant) — Релевантно | T (Time-bound) — Ограниченно во времени*

Собрать ресёрч (минимум: OpenSpec, BMAD + 2–3 других актуальных SDD-инструмента) с описанием концепции, устройства, сильных/слабых сторон и сравнительной таблицей относительно todo-md. Результат — один markdown-документ в репозитории.

## 2. Context and Scope (Контекст и Границы)
*   **Где делается:** новый документ ресёрча, например `docs/research/SDD-comparison.md` (папку создать при необходимости).
*   **Инструмент ресёрча:** скилл `knowledge-extraction` (TasK API) — загрузить найденные материалы в проект и «поговорить» с ними через chat/search. Методология — в разделе 9.
*   **Текущее поведение:** Сравнения с SDD-инструментами нет; README не объясняет позиционирование относительно этого класса.
*   **Границы (Out of Scope):**
  - Сам раздел в README — **отдельная** задача (делается позже на базе этого ресёрча).
  - Глубокий технический разбор кода конкурентов — не нужно, достаточно концептуального обзора по их докам/обзорам.
  - Интеграция/копирование фич конкурентов в todo-md — не входит.

- [ ] По каждому инструменту: что это, как устроено (формат спецификации, workflow, роль AI/агентов), целевая аудитория, сильные/слабые стороны.
- [ ] Сравнительная таблица todo-md vs SDD-инструменты по ключевым осям: формат хранения (markdown/YAML), связь с кодом, workflow задач, роль AI, портативность, зависимости, зрелость.

## 4. Implementation Plan (План реализации)
*Пошаговый план работ. Заполняется исполнителем (агентом) перед стартом.*

### Этап 1. Сбор материалов
1. [ ] Выписать исходные URL: 2 видео из «Источников» + найти оригинальные доки/репозитории OpenSpec, BMAD.
2. [ ] Подобрать ещё 2–3 актуальных SDD-инструмента (например: spec-kit, GitHub Spec, аналоги из AI-coding) и ссылки на их доки.

### Этап 2. Загрузка в TasK (скилл knowledge-extraction)
3. [ ] Создать проект и загрузить материалы: `ingest.sh --source-url <URL>` для каждого источника (видео, статьи, доки).
4. [ ] Дождаться `ready` по всем источникам через `ingest.sh --check` (YouTube-видео могут транскрибироваться десятками минут — грузить асинхронно, работать с готовыми).

### Этап 3. Диалог с материалами
5. [ ] Начать чат по всему набору: `scripts/chat.sh --title "SDD-ресёрч"` (без `--source` — берёт все источники проекта).
6. [ ] Атомарные уточняющие вопросы по каждому инструменту: «Как устроено?», «Формат спецификации?», «Роль AI/агентов?», «Сильные/слабые стороны?» — каждый вопрос отдельным вызовом через `--chat <UUID>` (один вопрос — одна тема).
7. [ ] Если чат даёт странные ответы — сверить точные формулировки через `search.sh --source <UUID> --query "..."`.

### Этап 4. Синтез и оформление
8. [ ] Свести общее определение SDD и общие признаки подхода.
9. [ ] Заполнить карточку по каждому инструменту (концепция / устройство / роль AI / плюсы-минусы) на основе добытых тезисов и цитат.
10. [ ] Построить сравнительную таблицу с todo-md.
11. [ ] Написать блоки «сходство / отличие / позиционирование» и выводы.
12. [ ] Положить документ в `docs/research/`, проверить ссылки.

## 7. Risks and Dependencies (Рisks and Dependencies)
*Потенциальные проблемы, блокеры, внешние зависимости.*

- Риск: субъективность оценок «лучше/хуже» — опираться на факты (формат, зависимости, workflow), а не на вкусовщину.
- Зависимость: доступ к видео/докам — ссылки уже есть в «Источниках».
- Зависимость: скилл `knowledge-extraction` + действующий `.task_token.json` в корне проекта (без токена ресёрч через TasK невозможен).

## 9. Comments (Комментарии)
*Дополнительная информация, примечания, важные нюансы.*

- **Методология ресёрча (skill-based):** не читать материалы целиком в контекст, а загрузить их в проект TasK через скилл `knowledge-extraction` и «поговорить» с ними (chat — приоритет, search — запасной). Workflow:
  1. `ingest.sh --source-url <URL>` для каждого источника (видео, статьи, доки) → проект создаётся/пополняется, маппинг URL→source_uuid кешируется в `.task_project.json`.
  2. `ingest.sh --check` — дождаться `ready` по всем источникам (YouTube-видео могут обрабатываться десятками минут).
  3. `chat.sh --title "SDD-ресёрч"` — начать диалог по всему набору; уточнять **атомарными** вопросами через `--chat <UUID>` (один вопрос — одна тема).
  4. Точные цитаты сверять через `search.sh --source <UUID> --query "..."`.
  5. На основе добытых тезисов собрать документ ресёрча; утверждения подтверждать ссылками на источники.
- Источник запроса — пользователь упомянул OpenSpec и BMAD из двух видео выше. Найти в видео, что именно про них говорится, и использовать как отправную точку.
- **Этот ресёрч — база для следующей задачи:** создание раздела в README про позиционирование todo-md относительно SDD. Раздел в README заводится отдельной задачей после согласования выводов ресёрча.
- Желаемый язык документа — русский, с английскими терминами в скобках при первом упоминании (по конвенции проекта).
