# TASK-cli-env-model-autofill: Автозаполнение модели и уровня мышления в create/start

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
Постановщики и исполнители создают задачи и стартуют их с голой ролью — `Разработчик (pi)`. Модель и уровень мышления в полях `author`/`assignee` не попадают, хотя источник истины для них есть (окружение харнесса, профиль роли). Из-за этого в задачах нет данных «кто на чём реально работал»: срез по моделям пуст, статистика стоимости и качества по моделям не строится, а агенты полагаются на самоописание модели, которое LLM даёт недостоверно.

### Варианты или путь решения (Solution Sketch)
- В `create` и `start` принимать модель и уровень явными ключами `--model=<модель>` / `--thinking=<уровень>` и дописывать `@модель~уровень` к участнику вида `Роль (агент)`; CLI не читает переменные окружения — значение передаётся ключом из источника истины (env харнесса или профиль роли) и работает для любого агента.
- Невалидный ввод и значения вне списков `models`/`thinking_levels` конфига проекта — понятная ошибка, а не молчаливая подмена; заданное явно не перезаписывать.

### Ожидаемый результат (Expected Result)
Новые задачи и старты фиксируют модель и уровень мышления по явному ключу: `todo-md create ... --model=glm-5.3-flash --thinking=high` даёт `author: Разработчик (pi@glm-5.3-flash~high)` уже при создании. Окружение в CLI не читается, значения вне списков конфига дают понятную ошибку, старые задачи не затронуты.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> Как владелец проекта, я хочу, чтобы в задачах фиксировались модель и уровень мышления исполнителя по явному ключу CLI, чтобы видеть срез «кто, на чём и на каком уровне работал» без ручного редактирования front matter.

### Цель по SMART (Goal)
- [ ] `create --model/--thinking` дописывает `@модель[~уровень]` в `author`, `start --model/--thinking` — в `assignee`; ключи работают для любого агента, окружение CLI не читает.
- [ ] Уже указанная модель не перезаписывается (`--model` — ошибка); `--thinking` требует `--model`.
- [ ] Невалидный ввод и значения вне `models`/`thinking_levels` конфига проекта дают понятную ошибку, а не молчаливую подмену.

## 2. Контекст и Границы (Context and Scope)

*   **Где делаем:** `src/TodoMd/Board.php` (`withModel`, `create`, `transition`), `src/bootstrap.php` (`cli_create`, `cli_transition`, help).
*   **Текущее поведение:** `create` пишет `author` как передан; `start` пишет `assignee` как передан; модель и уровень нигде не заполняются.
*   **Прецеденты для переиспользования:** `docs/todo-md/reference/MODELS.md` — формат участника, словари уровней `Parser::THINKING_LEVELS`, правило «источник истины — env харнесса».
*   **Критичные конвенции:** формат участника `Роль (агент[@модель[~уровень]])` и его проверка — `Validator::validateActor`.
*   **Границы (Out of Scope):** валидатор не меняется (наследие старых задач без модели остаётся валидным); обогащение полей `reviewer`/`approver`/`consultants`/`informed` и команды `set` не входит в задачу; для не-pi агентов переменные окружения не изыскиваются.
