# TASK-todo-md-lifecycle-dates: Поля жизненного цикла задач (due/started/completed)

## 0. Простое описание (Human Brief)
### Проблема простыми словами (Problem)
- В схеме задач и эпиков есть только `created`. Нет дат жизненного цикла: планового срока, старта, завершения.
- Без них нельзя строить диаграммы Ганта по времени, видеть просрочку, считать lead/cycle time.
- Это блокирует Гант-часть генератора отчётов (см. [сводный анализ 2026-07-25, №3](../../docs/research/2026-07-25-top-ideas-for-agent-and-human-ux.md)).

### Варианты или путь решения (Solution Sketch)
- Добавить в front matter задач и эпиков необязательные поля `due`, `started`, `completed` (дата `YYYY-MM-DD`).
- Описать поля в справочнике, обновить шаблоны, валидатор проверяет формат дат при заполнении.

### Ожидаемый результат (Expected Result)
- В новых задачах есть стандартное место для дат жизненного цикла.
- Генератор Ганта получает данные для оси времени; существующие задачи не ломаются.

## 1. Концепция и Цель (Concept and Goal)
### История (User Story)
> Как владелец проекта, я хочу фиксировать срок и фактические даты прохождения этапов задачи, чтобы строить диаграммы Ганта и видеть просрочку.

### Цель по SMART (Goal)
Добавить необязательные поля `due`/`started`/`completed` (дата `YYYY-MM-DD`) в front matter задач (TASK) и эпиков (EPIC): описать в справочнике, обновить шаблоны `task.md`/`epic.md`, валидатор проверяет формат дат при заполнении. Поля optional — обратная совместимость сохраняется.

## 2. Контекст и Границы (Context and Scope)
*   **Где делаем:** `docs/todo-md/templates/task.md`, `docs/todo-md/templates/epic.md`, `docs/todo-md/reference/` (новый `DATES.md` или раздел в существующем справочнике), `bin/todo-md-validate`.
*   **Текущее поведение:** есть только поле `created`.
*   **Границы (Out of Scope):**
    *   Автоматический сбор дат (как и с `cost_*` — пока заполняется вручную).
    *   Metrics/reports (lead/cycle time) — отдельная задача.
    *   Urgency score, recurring tasks, `scheduled`/`defer_until`.

## 3. Требования, MoSCoW (Requirements)
### 🔴 Обязательно (Must Have)
- [ ] Поля `due`, `started`, `completed` (дата `YYYY-MM-DD`) в шаблонах task и epic, необязательные.
- [ ] Описание полей и семантики в справочнике.
- [ ] Валидатор: если поле заполнено — проверка формата даты; пустое — допустимо.
- [ ] Существующие задачи остаются валидны (поля optional).

### 🟡 Желательно (Should Have)
- [ ] Пример заполнения в шаблоне.
- [ ] Семантика зафиксирована: `started` — переход в `in_progress`; `completed` — переход в `done`; `due` — плановый срок.

### 🟢 Опционально (Could Have)
- [ ] Поле `updated` (дата последнего изменения) — но требует auto-update, вероятно отложить.

### ⚫ Не будем делать (Won't Have)
- [ ] Автозаполнение дат агентом/скриптом.
- [ ] `scheduled`/`defer_until`, recurring tasks.


## 7. Риски и зависимости (Risks and Dependencies)
- Формат даты должен быть единым (`YYYY-MM-DD`, ISO 8601); иначе валидатор и генератор Ганта сломаются.
- Семантика `started`/`completed` должна совпадать со статусами (`in_progress`/`done`), иначе противоречие в модели.
- Зависимость-потребитель: генератор дашбордов/Ганта (research 2026-07-25, №3) — Гант по времени невозможен без этих полей.

## 9. Комментарии (Comments)
Гант по времени невозможен без этих дат; дашборд (без оси времени) строится и сейчас. Поэтому задача — prerequisite для Гант-части №3, но не для её дашборд-части. Поля optional по аналогии с `cost_plan`/`cost_fact`: фиксируем место, автозаполнение не делаем.
