# TASK-cli-history-command: Команда history — строка «Истории изменений» с датой от CLI и участником по явным ключам

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Команды для строки «Истории изменений» нет — таблица ведётся руками (`docs/todo-md/AGENTS_TASK_WRITING_GUIDE.md:103`). Агент набирает дату на глаз и копирует участника из соседних строк.
- Последствия в проекте-потребителе `stocks2`: строки предыдущих сессий несут unix-метку на 7 часов впереди подписи при «круглых» секундах; то же повторялось в ретро проекта 2026-09-02 и 2026-09-14. 2026-11-23 сессия на `pi@glm-5.4~high` записала в три задачи модель соседней строки, `pi@glm-5.3-flash~high`.
- Для `created`, `started`, `completed` дату ставит CLI. В истории источником даты остаётся агент.

### Варианты или путь решения (Solution Sketch)
- Новая команда. Строку добавляет CLI, участника задают явными ключами — те же, что у `create` и `start`:
```bash
php bin/todo-md history TASK-x "Постановка уточнена" --role="Разработчик" --model="$PI_MODEL" --thinking="$PI_REASONING_LEVEL"
```
- После записи файл валидируется; при ошибке восстанавливается прежнее содержимое.

### Ожидаемый результат (Expected Result)
- Строка истории появляется одной командой. Дата всегда согласована с unix-меткой, участник записан по явным ключам. Ручной набор даты больше не нужен.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> Как агент, работающий с задачами, я хочу добавлять строку истории командой с явными ключами, чтобы дата и участник были корректными без ручного набора.

### Цель по SMART (Goal)
- В следующем минорном релизе команда `history` добавляет строку в «Историю изменений» с датой CLI и участником по явным ключам. Каждое правило покрыто тестом, документация и `CHANGELOG.md` обновлены, `make check` зелёный.

## 3. Требования, MoSCoW (Requirements)
### 🔴 Обязательно (Must Have)
- [x] Синтаксис `history <ID> "<изменение>" --role="<Роль>" [--model=<модель> --thinking=<уровень>]`. `--role` обязателен; модель и уровень добавляются к участнику через `Board::withModel` — те же правила, что у `create` и `start`.
- [x] Строка `| <дата> (<unix-ts>) | <Роль> (<агент>@<модель>[~<уровень>]) | <изменение> |` вставляется после последней строки таблицы раздела «История изменений». Дата — `now()` CLI в формате `DATES.md`.
- [x] Стиль перевода строк и отсутствие завершающего перевода строк сохраняются.
- [x] После записи файл валидируется (`Validator::checkOnBoard`); при ошибке прежнее содержимое восстанавливается, команда завершается с ошибкой.
- [x] `|` и переводы строк в тексте — ошибка, файл не меняется.
- [x] Задача не найдена или раздел истории в файле отсутствует — ошибка, файл не меняется.
- [x] Вывод команды — добавленная строка.
- [x] Тесты на каждое правило.
- [x] Документация: README (команда), `AGENTS_TASK_WRITING_GUIDE.md` (история ведётся командой), комментарий в шаблоне задачи; `CHANGELOG.md`.
- [x] `make check` зелёный.

- Чтение участника из окружения харнесса внутри CLI.

## 9. Комментарии (Comments)
- Задача поставлена из проекта-потребителя `stocks2` по решению владельца: проблема общая для проектов, надстройка в потребителе отвергнута (prikotov/stocks2#465 закрыт).

    - В примере DoD (раздел 5) голая роль `--role="Разработчик"` с `--model` давала бы `Разработчик (pi@glm-x~high)` — но Must Have требует «те же правила, что у `create` и `start`», а `Board::withModel` осмысленно обогащает только `Роль (агент)`; подстановка агента по умолчанию выдумывала бы данные.     - Проверка колонки «Автор» (Should Have) — всегда warning, в `--strict` не эскалируется до ошибки: колонка append-only («записи не удаляются и не переписываются»), старые строки нельзя ретроконформировать (в пакете 6 строк `Тимлид (Алекс)` до формата v0.2.0); строгая ошибка сделала бы `validate --strict` навсегда красным для проектов со старой историей.
    - По ходу закрытия задачи 1 (PR #46) при закрытии задачи в git остался отслеживаться фантомный дубль файла в `todo/` — урок: при завершении задач коммитить перемещение `todo/ → done/` целиком (`git add -A todo/`).
    - По замечанию владельца при ревью: упоминание команды `history` убрано из шаблонов задачи/эпика — шаблон про «ЧЕМ заполняется», инструкция CLI («КАК») живёт в гайде и README.
