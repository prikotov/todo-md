# TASK-docs-clarify-task-branch-lifecycle: Clarify task branch lifecycle

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
Инструкция предлагает создать файл задачи и изменить его состояние до создания рабочей ветки. Это противоречит правилам проектов, запрещающим любые правки в целевых ветках. Кроме того, описание пакета указывает несуществующий путь исходных правил, из-за чего исправления можно внести не туда.

### Варианты или путь решения (Solution Sketch)
Разделить оформление постановки и начало реализации, создавать или выбирать рабочую ветку до изменения файлов, а расположение исходных правил описать по реальному установщику.

### Ожидаемый результат (Expected Result)
Создание и выполнение задач не требуют правок в защищённых ветках, а сопровождающий пакет знает, какой файл распространяется потребителям.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> Как участник проекта, я хочу однозначный порядок подготовки задачи и рабочей ветки, чтобы не нарушать правила публикации изменений.

### Цель по SMART (Goal)
В текущем PR согласовать документацию о создании задачи, начале реализации и поле `branch`, исправить описание исходного `todo/AGENTS.md`; подтвердить результат командой `make check` и независимым ревью.

## 2. Контекст и Границы (Context and Scope)
- Основные файлы: `todo/AGENTS.md`, `AGENTS.md`, непосредственно связанные инструкции и шаблоны в `docs/todo-md/`.
- Источник распространяемых правил — `todo/AGENTS.md`, что подтверждено установщиком в `src/bootstrap.php`.
- Работа идёт в отдельном рабочем каталоге; незакоммиченные изменения исходного checkout не затрагиваются.
- Не менять CLI, формат хранения, валидацию, зависимости и посторонние задачи.
