# Список LLM-моделей (Models)

Используйте эти идентификаторы для опционального поля `model` в задачах и эпиках. Поле фиксирует модель исполнителя, выполнявшего основную работу, и используется для аналитики в дашборде (распределение done-задач по моделям).

## Модель и роли

В конвейере над одной задачей обычно работает несколько ролей (постановка → реализация → самопроверка → ревью), и каждая роль закреплена за своей моделью в конфиге проекта (профиль роли, например `config/chains.yaml`). Поэтому:

- **Первичный источник привязки «роль → модель» — конфиг ролей проекта.** Задача его не дублирует.
- **`model` на задаче — модель исполнителя** (`assignee`), срез на момент работы. Это историческая запись для аналитики: конфиг ролей меняется, а done-задача должна помнить, какая модель реально её выполнила (аналогично `cost_fact`).
- Модели других участников (author, reviewer, консультанты) в задачу не записываются — они восстанавливаются из профилей ролей на момент работы.

## Формат

- Lowercase-идентификатор с опциональным тегом: `[a-z0-9][a-z0-9.:_-]*`. Примеры: `gpt-4o`, `claude-sonnet-4`, `huihui-ai:pi-100k`.
- Поле опциональное, заполняется вручную: оркестратор при назначении исполнителя (из профиля роли) либо исполнитель из окружения своего харнесса (например, `PI_MODEL` / `PI_PROVIDER` у pi) — не из «самоописания» модели, LLM угадывает свою модель недостоверно.
- Не участвует в workflow (в отличие от `author`/`assignee`).

## Валидация

Валидатор `todo-md validate` проверяет:

- формат (lowercase-идентификатор);
- вхождение в канонический список (см. выше) — нарушение выводится как warning, в режиме `--strict` или `strict: true` — как error;
- пустое значение допустимо всегда.

Список можно заменить или расширить через конфиг `.todo-md.php` (`models`) — см. [CONFIG.md](./CONFIG.md). Новые модели, которых нет в списке, добавляйте в конфиг своего проекта.

## Пример

```yaml
assignee: Бэкендер (pi)      # роль исполнителя
model: glm-5.3-flash          # её модель из профиля роли (chains.yaml)
```

Ревью задачи выполнял другой участник на другой модели (например, локальный ревьювер на ollama) — в поле `model` это не попадает: привязка «ревьювер → модель» живёт в конфиге ролей проекта.
