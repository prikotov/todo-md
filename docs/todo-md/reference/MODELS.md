# LLM-модели участников (Models)

Модели указываются **в составе участника** — в полях `author`, `assignee`, `reviewer`, `approver`, `consultants`, `informed` задач и эпиков.

## Формат участника

```
<роль> (<агент>[@<модель>[~<уровень>]])
```

- `роль` — функциональная обязанность (`Бэкендер`, `Продакт`); см. [ROLES.md](./ROLES.md).
- `агент` — lowercase-идентификатор инструмента (`pi`, `codex-cli`); см. [AI_AGENTS.md](./AI_AGENTS.md).
- `модель` — lowercase-идентификатор: `[a-z0-9][a-z0-9.:_~-]*` (двоеточие — ollama-теги, тильда допустима внутри имени).
- `уровень` — lowercase-слово reasoning/thinking: `off`, `minimal`, `low`, `medium`, `high`, `max`; только после модели.

Разделители: `@` — агент→модель; `~` — уровень мышления после модели.

## Модель и роли

Модель закреплена **за ролью** — в конфиге проекта хранится профиль роли (провайдер, модель, уровень мышления), например `config/chains.yaml`. Задача фиксирует **срез**: кто и на какой модели реально выполнял работу. Конфиг ролей меняется со временем, а записи участников в done-задаче остаются исторической правдой.

Правила заполнения:

- Указывать модель **рекомендуется** для всех участников; уровень мышления — когда профиль роли его задаёт.
- Источник истины для агента — окружение его харнесса (например, `PI_MODEL` / `PI_PROVIDER` / `PI_REASONING_LEVEL` у pi) или профиль его роли, а не «самоописание» модели: LLM угадывает свою модель недостоверно.
- Запись без модели (`Продакт (pi)`) остаётся валидной — для участников, чья модель не важна или неизвестна.

## Как называть модель

Идентификатор берите из документации провайдера или профиля роли **на момент работы**. Примеры (иллюстративные, со временем стареют):

- `glm-5.3-flash`, `glm-5.3` — Z.AI (GLM)
- `k3.1-pro` — Kimi
- `mimo-v2.6-pro` — Xiaomi MiMo
- `deepseek-flash` — DeepSeek
- `huihui-ai:pi-100k` — локальная модель ollama с тегом

Требования к идентификатору: lowercase, `[a-z0-9][a-z0-9.:_~-]*`; дублирование одного и того же имени в разных написаниях не допускается — иначе аналитика размоется.

## Уровни мышления (Thinking)

Уровень — **свободное lowercase-слово после `~`**: словари reasoning/thinking у разных харнессов не совпадают, поэтому пакет не фиксирует закрытый список значений. Словарь пакета нужен только для распознавания разделителя `~` (отличить `модель~уровень` от тильды внутри имени модели) — это объединение словарей основных харнессов:

- pi: `off`, `low`, `medium`, `high`, `max` (см. `--thinking`, `PI_REASONING_LEVEL`);
- codex-cli: `minimal`, `low`, `medium`, `high` (reasoning effort);
- прочие харнесса — свободное слово или числовой бюджет (бюджеты в токенах записать словом нельзя — для них уровень опускайте или зафиксируйте в тексте задачи).

Правила:

- уровень указывается только вместе с моделью: `Бэкендер (pi@glm-5.3-flash~max)`, `Аналитик (codex-cli@gpt-5~minimal)`;
- значение уровня по умолчанию не проверяется; для проверки задайте `thinking_levels` в конфиге проекта (для смешанных команд pi + codex-cli задавайте объединение словарей) — см. [CONFIG.md](./CONFIG.md);
- неизвестный суффикс после известной модели признаётся опечаткой уровня (warning).

Одна модель на разных уровнях мышления — разные конфигурации по стоимости и качеству (`glm-5.3-flash~high` и `glm-5.3-flash~max`), поэтому уровень входит в срез наряду с моделью.

## Валидация

Валидатор `todo-md validate` проверяет модель и уровень в составе каждого участника:

- **формат** — всегда: lowercase-идентификатор `[a-z0-9][a-z0-9.:_~-]*`, уровень — lowercase-слово после `~`;
- **уровень мышления** — суффикс `~<слово>` считается уровнем, только если слово из словаря распознавания (см. выше); иначе — часть имени модели; значения уровней по умолчанию не проверяются;
- **список моделей** — если проект задал `models` в конфиге `.todo-md.php`, значения проверяются по нему; без списка — только формат.

Нарушения — warning, в режиме `--strict` или `strict: true` — error. См. [CONFIG.md](./CONFIG.md).

## Пример

```yaml
author: Продакт (pi@k3.1-pro~low)              # постановщик на Kimi, low
assignee: Бэкендер (pi@glm-5.3-flash~max)      # исполнитель на GLM Flash, max
reviewer: Ревьюер (pi@huihui-ai:pi-100k~medium) # ревью на локальном ollama, medium
```
