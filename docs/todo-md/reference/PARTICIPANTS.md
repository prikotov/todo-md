# Участники подготовки постановки

Необязательные поля YAML front matter (блока метаданных) задачи или эпика:

| Поле | Назначение | Значение |
| :--- | :--- | :--- |
| `consultants` | Консультанты | Список участников |
| `reviewer` | Проверяющий постановку | Один участник или пусто |
| `approver` | Принимающий постановку | Один участник или пусто |
| `informed` | Оповещаемые | Список участников |

Участника записывают в формате `Роль (агент)`, как в `author` и `assignee`. Роли и состав участников определяет команда по своей матрице ответственности. Пакет не назначает участников автоматически.

`author` остаётся создателем документа, `assignee` — исполнителем задачи или эпика. Новые поля не дублируют их и не назначают проверяющего кода или принимающего реализацию.

Для эпика подготовка включает создание, уточнение и декомпозицию. Поля хранят один актуальный состав участников подготовки. При изменении состава обновляют поля и фиксируют изменение в истории документа. Одновременные назначения по нескольким этапам этим форматом не описываются.

## Запись

```yaml
consultants: ["Архитектор (pi)", "Тестировщик (codex)"]
reviewer: Аналитик (pi)
approver: Тимлид (pi)
informed: []
```

Вместо строчного списка можно использовать блочный с одинаковым отступом из пробелов:

```yaml
consultants:
  - Архитектор (pi)
  - Тестировщик (codex)
reviewer:
approver:
informed: []
```

- Пустой список — `[]`; пустой блочный список также читается как `[]`.
- Кавычки вокруг строки необязательны. В строчном списке значение с запятой заключают в кавычки.
- В одинарных кавычках апостроф удваивается; в двойных поддерживаются экранирования JSON, например `\"` и `\\`.
- Комментарии после значения отделяют пробелом и `#`; символ `#` внутри кавычек остаётся частью строки.
- Вложенные структуры, многострочные строки, якоря и псевдонимы YAML не поддерживаются.

## Проверка и изменение

Старые файлы без новых полей остаются допустимыми. Пустые назначения разрешены при любом статусе: готовность постановки определяет процесс команды, а не валидатор.

Ошибки структуры, повтор поля или дубликат внутри списка приводят к ошибке проверки. Формат участника и известные роли/агенты проверяются по тем же правилам, что `author` и `assignee`: предупреждение по умолчанию, ошибка с `--strict` или `strict: true` в [конфигурации](CONFIG.md).

Команда `set` (изменение метаданных) заменяет список целиком. При ошибке проверки все изменения команды откатываются. Переходы статусов сохраняют назначения.

```bash
php vendor/bin/todo-md set TASK-example 'consultants=["Архитектор (pi)"]' 'reviewer=Аналитик (pi)'
php vendor/bin/todo-md set TASK-example 'consultants=[]' 'reviewer='
php vendor/bin/todo-md validate TASK-example --strict
```

## Экспорт

В `export-jsonl` (экспорте JSON Lines) поля `consultants` и `informed` — массивы строк, `reviewer` и `approver` — строки или `null`. Для отсутствующих полей экспортируются соответственно `[]` и `null`. Некорректная структура участников останавливает экспорт с ошибкой, а не теряется молча.
