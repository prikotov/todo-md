# Роли (Roles)

Роль — это функциональная обязанность в проекте (позиция/должность), указываемая в полях `author` и `assignee` задач и эпиков перед идентификатором агента в скобках.

**Формат:** `<роль> (<агент>)`

Пример: `Бэкендер (codex-cli)`

## Канонические роли

Ниже приведён список общепринятых ролей для программных проектов. Проект может расширить этот список или переопределить его через конфиг `.todo-md.php` — см. [CONFIG.md](./CONFIG.md).

### Технические роли

| Роль | Описание |
| --- | --- |
| **Бэкендер** | Разработка серверной логики, API, баз данных, бизнес-логики |
| **Фронтендер** | Разработка пользовательского интерфейса, веб-клиентов |
| **Девопс** | Инфраструктура, CI/CD, деплой, контейнеризация |
| **Архитектор** | Проектирование архитектуры приложения, границ модулей, интеграций |
| **Тестировщик** | Тестирование, test-планы, контроль качества |

### Аналитика и продукт

| Роль | Описание |
| --- | --- |
| **Аналитик** | Сбор требований, бизнес-анализ, написание постановок |
| **Продакт** | Управление продуктом, приоритизация, roadmap |

### Документация и коммуникация

| Роль | Описание |
| --- | --- |
| **Технический писатель** | Написание и обновление технической документации |
| **Маркетолог** | Маркетинг, продвижение, коммуникации |

### Управление

| Роль | Описание |
| --- | --- |
| **Team Lead** | Руководство командой, координация, планирование |

## Использование ролей

- Роль указывается в поле `author` (автор задачи) и `assignee` (исполнитель).
- Роль проверяется валидатором `todo-md validate`:
  - Если в конфиге `.todo-md.php` задан список `roles` — роль проверяется по этому списку.
  - Если список `roles` пуст или отсутствует — роль не валидируется по значению, только по формату (текст перед скобками).
- Формат роли: текст на русском (или английском), пробел, затем агент в скобках.
- Роль не должна быть пустой или содержать только агента.
