# Конфигурация пакета (.todo-md.php)

Локальный конфиг пакета `todo-md`. Опциональный — при отсутствии пакет использует дефолтную конфигурацию.

## Где искать

Файл `.todo-md.php` кладётся в **корень проекта** (там же, где директория `todo/`).
Валидатор подгружает его автоматически. Путь можно указать явно:

```bash
php vendor/bin/todo-md validate --config=path/to/.todo-md.php
```

## Формат

PHP-файл, возвращает массив:

```php
<?php

declare(strict_types=1);

return [
    // Канонические роли проекта для автора, исполнителя и участников подготовки.
    // Если задано — роль (текст перед скобками) проверяется по этому списку.
    // Если пусто — роль не валидируется по значению, только по формату.
    'roles' => [
        'Бэкендер', 'Фронтендер', 'Девопс', 'Аналитик', 'Архитектор',
        'Продакт', 'Технический писатель', 'Тестировщик', 'Маркетолог', 'Team Lead',
    ],

    // Канонические агенты проекта (расширяет/переопределяет список из AI_AGENTS.md).
    // Агент — lowercase-идентификатор [a-z0-9_-] в скобках: `Бэкендер (codex-cli)`.
    // Если пусто — используется канонический список из AI_AGENTS.md.
    'agents' => [
        'codex-cli', 'codex', 'pi', 'kilocode', 'gemini-cli', 'opencode', 'roocode',
        // проектные персоны/слаги:
        'sherlock', 'levsha', 'phileas', 'aragorn',
    ],

    // LLM-модели проекта для моделей в составе участников (см. MODELS.md).
    // Если задано — модели проверяются по этому списку; если пусто/отсутствует —
    // только по формату (модели выходят часто, закрытого списка в пакете нет).
    // 'models' => [
    //     'glm-5.3-flash', 'k3.1-pro', 'huihui-ai:pi-100k',
    // ],

    // Уровни мышления для моделей в составе участников (см. MODELS.md).
    // По умолчанию — объединение словарей основных харнессов (pi, codex-cli).
    // Для смешанных команд задавайте объединение своих словарей:
    // 'thinking_levels' => ['off', 'minimal', 'low', 'medium', 'high', 'max'],

    // Нарушения формата и справочников участников считать ошибками (аналог --strict).
    // По умолчанию false — нарушения выводятся как warnings.
    'strict' => false,
];
```

### Валидация моделей участников

Модель и уровень мышления указываются в составе участника — `<роль> (<агент>[@<модель>[~<уровень>]])` — в полях `author`, `assignee`, `reviewer`, `approver` и списках `consultants`, `informed`. Отдельного поля `model` в front matter нет. См. [MODELS.md](./MODELS.md).

- **Формат** — модель и уровень опциональны: `Бэкендер (pi)`, `Бэкендер (pi@glm-5.3-flash)` или `Бэкендер (pi@glm-5.3-flash~max)`; идентификатор модели — lowercase `[a-z0-9][a-z0-9.:_~-]*` (тильда допустима внутри имени), уровень — lowercase-слово.
- **Список моделей** — закрытого списка в пакете нет (модели выходят часто). Если в конфиге задан `models`, модели проверяются по нему; без списка — только формат.
- **Уровень мышления** — суффикс `~<слово>` считается уровнем только если слово из словаря распознавания (по умолчанию — объединение словарей pi и codex-cli: `off/minimal/low/medium/high/max`; переопределяется через `thinking_levels`); иначе — часть имени модели; указывается только вместе с моделью.
- **Отсутствие модели** допустимо всегда; нарушение формата или списков — warning (в `strict` — error).

Пример включения проверки списка:

```php
'models' => ['glm-5.3-flash', 'k3.1-pro', 'huihui-ai:pi-100k'],
'thinking_levels' => ['off', 'high', 'max'],
```

### Валидация полей author/assignee

Конфиг определяет, какие значения допускаются в полях `author` и `assignee` задач и эпиков. Те же проверки формата, роли и агента применяются к заполненным `reviewer`, `approver` и каждому элементу `consultants`, `informed`; эти [участники подготовки постановки](PARTICIPANTS.md) необязательны.

#### Что проверяет валидатор

1. **Обязательность**:
   - `author` должен быть заполнен всегда.
   - `assignee` может быть пустым для `backlog`, `todo` и `cancelled`, но должен быть заполнен для `in_progress`, `paused`, `blocked`, `review` и `done`.
2. **Формат** — заполненное значение должно быть `<роль> (<агент>[@<модель>[~<уровень>]])`, где агент — lowercase-идентификатор
   `[a-z0-9][a-z0-9_-]*`, модель и уровень — опциональны. Примеры: `Бэкендер (codex-cli)`, `Бэкендер (pi@glm-5.3-flash~max)`.
   - Запрещены: bare-значения без скобок (`codex-cli`, `backend_developer`),
     агенты с заглавной/кириллицей (`Codex`, `Шерлок`).
3. **Агент** — идентификатор в скобках должен быть в списке `agents` (из конфига, иначе —
   канонический список [AI_AGENTS.md](./AI_AGENTS.md)).
4. **Роль** — если в конфиге задан `roles`, роль проверяется по этому списку. Без `roles`
   роль свободная (проверяется только формат).

#### Строгость нарушений

## Зачем нужно

Единый канонический формат ролей, агентов и моделей позволяет строить корректные отчёты
(дашборд, распределение по исполнителям/ролям/агентам/моделям) без ручной нормализации
транслитерационных дубликатов (`Бэкендер` / `backend_developer` / `Backend Developer`).
