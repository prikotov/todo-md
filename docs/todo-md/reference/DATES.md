# Даты жизненного цикла (Lifecycle Dates)

Поля жизненного цикла фиксируют плановый срок и фактические моменты прохождения ключевых этапов задачи или эпика. Нужны для диаграммы Ганта, критического пути, параллельности, расчёта ресурсов и метрик EVA.

## Поля

- **`due`** — плановый срок (deadline), к которому задача или эпик должна быть готова.
- **`started`** — фактический момент начала работы: переход в статус `in_progress`.
- **`completed`** — фактический момент завершения: переход в статус `done`.
- **`cancelled`** — фактический момент отмены: переход в статус `cancelled`. Терминальная метка (как `completed`), взаимоисключающая с ним.

## Формат

Допустимы две формы:

1. **Календарная дата** — `YYYY-MM-DD`. Для грубых сроков (например, `due` = «конец недели»).
2. **Локальное время + UTC-источник** — `YYYY-MM-DD HH:MM:SS (UNIX_TS)`.

Вторая форма — основная для агентской работы, где задачи живут минуты:

```
2026-07-27 14:05:13 (1785150313)
```

- `2026-07-27 14:05:13` — локальное время машины-писателя, удобно для человека.
- `(1785150313)` — Unix timestamp (секунды с epoch, UTC) в скобках — **источник истины**. Все расчёты длительностей, Гант, EVA идут по timestamp.
- Сепаратор между датой и временем — пробел (допускается также `T`).

Правила:

- Пустое значение допустимо (поле ещё не заполнено).
- Не допускается «наивное» время без timestamp: `14:05:13` без `(…)` невалидно — для математики длительностей неоднозначность таймзоны фатальна.
- Локальная часть и timestamp проверяются на согласованность: их разность (подразумеваемый offset таймзоны) должна лежать в диапазоне `[-12:00, +14:00]` и быть кратной 15 минутам (покрывает все реальные зоны, включая `:30`/`:45`). Рассинхрон (ручная правка одной части без другой) ловится как ошибка; авто-исправления нет — метку нужно переписать корректно. Консистенцию при записи гарантирует CLI (обе части из одного `now()`).

## Кто проставляет

- Метки проставляет **CLI/агент**, не человек вручную:
  - `vendor/bin/todo-md create` → `created`,
  - `vendor/bin/todo-md start` (→ `in_progress`) → `started`,
  - `vendor/bin/todo-md done` (→ `done`) → `completed`.
  - `vendor/bin/todo-md cancel` (→ `cancelled`) → `cancelled`.
- Ручной ввод минутных меток не предполагается — это гарантированно мусорные данные. См. [STATUSES.md](./STATUSES.md) — раздел «CLI-команды для переходов».

## Семантика

- `started` проставляется при переводе `status` в `in_progress`.
- `completed` проставляется при переводе `status` в `done`.
- `cancelled` проставляется при переводе `status` в `cancelled` (задача отменена, а не завершена).
- `due` — целевой срок; не зависит от статуса и может стоять с момента планирования.
- В эпике поля отражают жизненный цикл самого эпика, а не отдельных задач.

## Согласованность со статусом

| Поле | Связанный статус |
| :--- | :--- |
| `started` | `in_progress` |
| `completed` | `done` |
| `cancelled` | `cancelled` |

Если `started`, `completed` или `cancelled` заполнены, соответствующий статус должен быть достигнут (или пройден). Обратное не обязательно: статус может стоять, а метка — нет (поле optional). `completed` и `cancelled` взаимоисключающие — задача завершается в один терминальный статус.

## Зачем нужны эти даты

В агент-нативной разработке проекты закрываются за минуты/часы, а не дни — поэтому нужна минутная точность, а не дневная:

- **Гант по оси времени** — интервалы `started` → `completed` относительно `due`.
- **Критический путь** — сумма длительностей по DAG зависимостей; день-гранулярность обнуляет его для агентских задач.
- **Параллельность и ресурсы** — реальные длительности позволяют планировать, что идёт параллельно, и считать загрузку агентов.
- **EVA** (BCWS/BCWP/ACWP, SPI/CPI) — плановый график против факта по времени и стоимости.
- **Просрочка** — `due` раньше текущего момента при незавершённой работе.

## Пример

```yaml
created: 2026-07-25 13:02:00 (1784973720)
due: 2026-07-27 18:00:00 (1785164400)
started: 2026-07-27 14:05:13 (1785150313)
completed: 2026-07-27 14:12:01 (1785150721)
```

Грубый случай (только дата):

```yaml
due: 2026-08-10
```

Отменённая задача (вместо `completed`):

```yaml
created: 2026-07-25 13:02:00 (1784973720)
started: 2026-07-27 14:05:13 (1785150313)
cancelled: 2026-07-27 14:30:00 (1785151800)
```
