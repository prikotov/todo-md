# Даты жизненного цикла (Lifecycle Dates)

Поля жизненного цикла фиксируют плановый срок и фактические даты прохождения ключевых этапов задачи или эпика.

## Поля

- **`due`** — плановый срок (deadline), к которому задача или эпик должна быть готова.
- **`started`** — фактическая дата начала работы: переход в статус `in_progress`.
- **`completed`** — фактическая дата завершения: переход в статус `done`.

## Формат

- Значение — дата в формате `YYYY-MM-DD` (ISO 8601).
- Пустое значение допустимо, если дата ещё неизвестна или поле не используется.
- Дата — календарная, без времени и таймзоны.

## Семантика

- `started` проставляется при переводе `status` в `in_progress`.
- `completed` проставляется при переводе `status` в `done`.
- `due` — целевой срок; не зависит от статуса и может стоять с момента планирования.
- В эпике поля отражают жизненный цикл самого эпика, а не отдельных задач.
- Поля заполняются вручную — автозаполнения дат нет (по аналогии с `cost_plan`/`cost_fact`).

## Согласованность со статусом

| Поле | Связанный статус |
| :--- | :--- |
| `started` | `in_progress` |
| `completed` | `done` |

Если `started` или `completed` заполнены, соответствующий статус должен быть достигнут (или пройден). Обратное не обязательно: статус может стоять, а дата — нет (поле optional).

## Зачем нужны эти даты

- Строить диаграмму Ганта по оси времени (`started` → `completed`, относительно `due`).
- Видеть просрочку: `due` раньше сегодняшней даты при незавершённой работе.
- Считать метрики lead/cycle time (в отдельной задаче).

## Пример

```yaml
created: 2026-07-25
due: 2026-08-10
started: 2026-07-27

```
