# План релиза v0.0.14

## Метаданные

- Тег релиза: `v0.0.14`
- Тип повышения версии: `patch`
- Обоснование выбранной версии: совместимые исправления и уточнения распространяемой документации и шаблонов
- База рабочей ветки: `master` (`c8b9832`)
- Рабочая ветка: `release/0.0.14`
- PR подготовки релиза в основную ветку: будет указан после создания PR
- Ответственный: владелец проекта
- Плановая дата публикации: 2026-09-16

## Состав

- Уточнено, что `branch` означает ветку реализации и остаётся пустым до её выбора.
- Git-процесс вынесен из документации формата задач в правила проекта.
- Исправлены инструкции `todo-md init` и описание источника распределяемого `todo/AGENTS.md`.
- Команды обязательных проверок теперь берутся из правил проекта-потребителя.

## Риски

- Изменений CLI, формата front matter и миграций данных нет.
- При повторном `init` без `--force` существующие пользовательские документы не перезаписываются; для получения обновлённых инструкций потребитель должен осознанно обновить их.

## Порядок публикации

1. Слить PR из `release/0.0.14` в `master` после успешного CI и одобрения.
2. Проверить совпадение содержимого ветки и коммита слияния.
3. Создать и отправить тег `v0.0.14` на проверенный коммит слияния.
4. Создать GitHub Release по существующему тегу.

## Проверки перед публикацией

- `composer validate --strict`
- `make check`
- CI репозитория успешен
- `git diff --check`

## Проверки после публикации

- GitHub Release `v0.0.14` указывает на ожидаемый SHA.
- Composer VCS metadata видит новую версию.
- Установка в пустой тестовый каталог создаёт документацию и `todo/AGENTS.md` из новой версии.

## Действия при проблеме после релиза

- Откат не используется; опубликованный тег не изменяется.
- Исправление выпускается новой patch-версией.
- Координация: GitHub Issue и задача в `todo/`.
