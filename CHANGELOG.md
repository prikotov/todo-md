# Changelog

## [0.4.0] — 2026-11-11

[Сравнение с v0.3.0](https://github.com/prikotov/todo-md/compare/v0.3.0...v0.4.0)

### Added
- `create` и `start` принимают модель и уровень мышления участника явными ключами `--model=<модель>` и `--thinking=<уровень>`: голая роль `Роль (агент)` становится `Роль (агент@модель~уровень)` в `author`/`assignee`; CLI не читает переменные окружения и работает для любого агента, уже указанная модель не перезаписывается (`--model` — ошибка), невалидный ввод и значения вне списков `models`/`thinking_levels` конфига проекта дают понятную ошибку
- README: описание ключей `--model` / `--thinking` в разделе «Команды смены состояния»

## [0.3.0] — 2026-11-04

[Сравнение с v0.2.0](https://github.com/prikotov/todo-md/compare/v0.2.0...v0.3.0)

### Added
- Флаг `--no-config` для `init`: полностью исключает `.todo-md.php` из записи — защита проектного конфига валидатора при `init --force` (работает и на свежей установке, и вместе с `--force`)

### Changed
- README: секция «Инициализация» документирует `--force` и `--no-config` и рекомендуемую комбинацию `init --force --no-config` для обновления документации без потери настроек валидатора

## [0.2.0] — 2026-11-04

[Сравнение с v0.1.0](https://github.com/prikotov/todo-md/compare/v0.1.0...v0.2.0)

### Added
- Модель и уровень мышления исполнителя в составе участника — формат `Роль (агент[@модель[~уровень]])` для `author`, `assignee` и полей подготовки постановки; запись без модели остаётся валидной
- Справочник [MODELS.md](docs/todo-md/reference/MODELS.md): правила записи моделей, привязка модель→роль через конфиг проекта, уровень мышления после модели
- Конфиг `.todo-md.php` валидирует участников по каноническим ролям, агентам и моделям проекта; с `validate --config=...` или `--strict` — строгая проверка по спискам

### Changed
- `AI_AGENTS.md` обогащён списком агентов, собранным из токенов дашборда
- Примеры шаблонов задач и эпиков, `PARTICIPANTS.md` и примеры истории изменений показывают модель и уровень мышления в записях участников

## [0.1.0] — 2026-09-19

[Сравнение с v0.0.14](https://github.com/prikotov/todo-md/compare/v0.0.14...v0.1.0)

Добавлены необязательные участники подготовки постановки: списки YAML, проверка, изменение и экспорт; старые задачи совместимы. Шаблон задачи и `create` дополняются пунктами «Прецеденты для переиспользования» и «Критичные конвенции» — контекст постановки (пути похожих use case, фикстур, паттернов и ссылки на конвенции проекта) указывается в самой задаче.

## [0.0.14] — 2026-09-16

### Changed
- Уточнено, что `branch` обозначает ветку реализации и остаётся пустым до её выбора
- Git-процесс и команды обязательных проверок берутся из правил проекта-потребителя, а не из документации формата задач

### Fixed
- Исправлены инструкции `todo-md init` и описание источника распределяемого `todo/AGENTS.md`

## [0.0.13] — 2026-09-12

### Fixed
- `validate <ID>` находит задачу во всех статусных папках, а неизвестный ID или несуществующий путь завершается с кодом `1` вместо ложного успеха

## [0.0.12] — 2026-08-22

### Changed
- Модель завершения задачи: `review` — проверка результата до передачи на приёмку (CI, self-review, доработки); `done` — результат передан на приёмку; при замечаниях приёмки задача возвращается из `done` в `review`
- Механика git-порядка (push, апрув, branch protection) убрана из документации формата задач — момент перевода в `done` определяет процесс проекта (например, пакет `prikotov/git-workflow`)
- `review --> done: Выполнена` в диаграмме переходов; п.5 «Завершение» — одно действие, «возврат из done» — в разделе CLI-команд

### Added
- Front matter `package: prikotov/todo-md` в распределяемые документы (кроме шаблонов) — атрибуция источника в проектах-потребителях

## [0.0.11] — 2026-08-20

### Fixed
- Точечный `validate <файл>` резолвит `depends_on`/`epic` по всему дереву задач проекта (включая `done/`, `cancelled/`, `backlog/`) — без ложных ошибок «references unknown ID»; валидируются по-прежнему только переданные файлы
- `set <ID> f1=v1 f2=v2 ...` применяет все присваивания одной атомарной записью (все или ничего, с rollback); аргумент без `=` и комбинация `status` с другими полями — явная ошибка вместо молчаливого игнорирования

## [0.0.10] — 2026-08-09

### Fixed
- Пустой `assignee` разрешён до начала работы и для отменённых задач; исполнитель обязателен только для статусов фактической работы и завершения

## [0.0.9] — 2026-08-09

### Added
- Сравнение todo-md с BMAD, Spec Kit и OpenSpec

### Changed
- Заголовки задач и эпиков приведены к формату «русский термин (English term)»
- Уточнены правила формулирования проблемы в Human Brief
- AI-комментарии в шаблонах задач и эпиков сделаны содержательнее и приведены к единому формату

## [0.0.8] — 2026-07-31

### Added
- HTML dashboard (`todo-md dashboard`) с визуализацией доски
- JSONL export (`todo-md export-jsonl`) для машинной обработки
- Валидация ссылок `depends_on` и `epic` — проверка существования целевых задач
- Lifecycle date fields: `due`, `started`, `completed`, `cancelled`
- Валидация формата datetime в Change History согласно DATES.md
- Кросс-проверка локального времени и Unix timestamp
- Команды атомарных переходов: `start`, `review`, `done`, `cancel`, `backlog`
- Валидация полей `author` и `assignee`
- Сводный анализ идей и аудит-роадмап (research)

### Changed
- Формат lifecycle-дат: локальное время + UTC timestamp
- Уточнена логика группировки эпиков в описании доски

### Fixed
- Закрыт незакрытый bash code block в документации
- Убран лишний пустой перевод строки после изображений в заголовке
- Убрана битая ссылка на несуществующий MODELS.md
